**Goal:** The checkpointed `messages` channel becomes the one short-term memory: it survives runs, carries tool calls and tool results, and is the only source of dialogue history for every phase (INV-LLM-001/002). Episodes end by rule — inactivity gap, committed phase transition, budget overflow — and a synchronous `compact` step turns the ended episode into one independent structured summary (max 3 kept, oldest first) before the next model call. `conversation_turns` becomes an append-only transcript projection of every message; the rolling asynchronous phase summary and the per-phase `PhaseLayout` (`history_frame`, `summaryFrame`, `toolResultsFrame`) disappear — one message shape for every phase. Facts (weights, reps, session state) never come from a summary.

**Architecture:** ADR-0013 §3.1–§3.3 (D-01, D-02; BR-LLM-001..004; INV-LLM-001..003), §3.4 blocks 2 and 4 (previous-episodes block; history from `messages`), §8 (`conversation_turns` kinds/payload, `conversation_summaries`), §4.1 as amended 2026-09-18 (`commit` raises `PhaseTransitionCommitted`; compaction is a handler that sets a flag; `prepare` runs `compact`). Master plan P4 items 1, 2, 4, 6. Owner decisions 2026-09-17 (`docs/STATE.md` § Blocked): one chat across the app; summaries at compaction, independent, never rolling; trivially short episodes trimmed without a summary; long-term fact extraction is P6 and consumes the summariser's structured output — this plan produces and stores that output, nothing more.

**Tech Stack:** TypeScript, LangGraph 1.1.5 (`messagesStateReducer`, `RemoveMessage`, `PostgresSaver.deleteThread` — present in the installed `@langchain/langgraph-checkpoint-postgres` 1.0.x, `dist/index.d.ts:139`), `LlmGateway.structured` (P1, `infra/ai/llm.gateway.ts`), one Drizzle migration, Jest, the eval stack (L0 snapshots, L1 runner).

**Spec:** ADR-0013 §3, §4.1, §8, §11; `docs/LLM_CORE_REFACTOR_PLAN.md` § P4 items 1, 2, 4, 6 and rollback; ADR-0010 (summary rationale, "facts only, no style"); `docs/PROMPT_EVAL_FRAMEWORK.md` §4.2 (harness seeding), §7a (cost gate).

**Acceptance criteria:** AC-1341 (second run of an episode sees the first run's tool calls and results — integration test with `MemorySaver` and a mocked model), AC-1342 (`EPISODE_GAP` mocked to 0 → the second run's input has exactly one episode-summary block and none of the first run's messages; one `conversation_summaries` row), AC-1345 (`conversation_turns` rows with `kind IN ('tool_call','tool_result')` grow on dev after a plan-creation smoke), AC-1346 (`grep -rn "getMessagesForPrompt\|getLatestSummary\|__context_reset__" apps/server/src` → empty), AC-1344 (L1: `plan_creation/id-reuse` ≥ +15 pp on `no_redundant_search` vs the `v2` baseline; all other datasets within ±2 pp; the L2 judge half is measured manually — no L2 runner exists in `evals/levels/`). AC-1343 (history budget enforcement) is `refactor-p4-context-budget`.

## Global Constraints

- **Behaviour-changing phase, gated by evals.** Phase prompt *wording* does not change (the `## Previous episodes` block and the summariser v2 are new module versions with their own ids, not edits to `phases/*/v1.ts`). L0 phase-prompt snapshots stay green. The message-assembly snapshots (`evals/snapshots/__tests__/message-assembly.unit.test.ts`) are regenerated **exactly once** (Task 5) with an enumerated diff pasted into this plan; the orchestrator reviews the diff before the next task starts.
- **Rollback unit = this plan** (master plan P4 rollback): one revert commit restores P3, which reads history from `conversation_turns` by `role IN ('user','assistant')` and the latest `role = 'summary'` row. Nothing here may make that path unrecoverable: the projection keeps writing `conversation_turns`, and D-K derives `role` so a P3 reader sees only real user/assistant text.
- **One migration**: the `conversation_summaries` table. The `conversation_turn_kind` enum and the `run_id`/`kind`/`payload` columns already exist (`drizzle/0002_conversation_runs.sql`). `npm run drizzle:generate` produces exactly one new file — **`0004_*`** (`0003_cool_thor_girl.sql` is taken by the P3 tails). The executor may apply it locally (`npm run db:local:migrate`); durable envs migrate via `deploy.sh` (orchestrator).
- **Compaction is synchronous and inside the run** (`prepare`), never fire-and-forget; on summariser failure it degrades to trimming without a summary and logs `warn` (BR-LLM-004). The legacy `phase-summary.node.ts`, `legacy-phase-summary.handler.ts`, `IConversationContextService` and both implementations are deleted.
- **A turn is never split**: a turn = one `HumanMessage` through the last message before the next `HumanMessage`; compaction removes whole turns, so an `AIMessage(tool_calls)` and its `ToolMessage`s always travel together. The unit test for "cut in the middle of a tool pair is impossible" is written first (master plan P4 note).
- **Every `tool_call` id gets a `ToolMessage`** (D-J). Once messages persist, an `AIMessage(tool_calls)` with an unanswered call would be replayed to the provider on the next run and rejected — the master plan's rollback trigger. The executor's `system_error` path is fixed in Task 4 before persistence is switched on.
- **Summaries carry no facts the prompt may act on**: the summariser prompt keeps ADR-0010's "facts only, no style" instruction *and* the block that renders summaries says they are context, not data — numbers come from tools (INV-LLM-003; owner rule).
- **No `@langchain/*` in `domain/**`** (AC-1333, ESLint rule). The new ports speak a domain `TranscriptMessage` type; the `BaseMessage` → `TranscriptMessage` mapping lives in infra (`commit`).
- **Reserved to the orchestrator:** Task 2 (freeze `v2`), Task 9. Verification commands run from `apps/server/`. No attribution lines in commits.
- **Cost gate (§7a, hardened 2026-09-18) — code first, model runs only when budget is left:** the executor runs **no** `RUN_LLM_EVALS=1` command that reaches a model. Unit tests, L0, mocked-model integration tests and the local DB integration suite are the whole verification surface of Tasks 1 and 3–8, and nothing in that path waits on a model run. **Exactly one model-backed run is on the plan's path, and it comes after all the code**: the Task 9 Step 1 working-check (≈ 9–10 calls, n=1) whose job is to surface errors, not to score. The 5-call `v2` mini-freeze (Task 2, on the Task 1 commit), the 5-call compare and the manual L2 rubric are the budget-gated micro-task `refactor-p4-evals-verify`; the full AC-1344 sweep is a red-button item. The plan merges and deploys on unit/integration/L0 + the working-check + the dev smoke, with AC-1344's statistics recorded as pending.
